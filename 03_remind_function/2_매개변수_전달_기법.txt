1. 매개변수 전달 기법
    1-1. Call by value
        => 값을 복사해서 전달합니다.
        => 이렇게 값을 복사해서 피호출자 함수에게 값을 전달하는 구조이고 큰 구조체를 연달아 넘기면? -> 1MB를 넘을 수 도 있습니다.
        => 그래서 포인터를 통해 자료구조를 구성하는 경우가 많습니다.
    1-2. Call by address
        => 복사하는 값이 메모리의 주소을 의미합니다.
    1-3. Call by refernce
        => 포인터로 구현합니다.
    1-4. 스택 구조를 관리하는 구조는 컴파일러가 넣어줍니다.
    1-5. 그래서 스택으로 관리되고 있는 메모리는 auto 키워드가 붙습니다.
    1-6. 매개변수도 스택을 사용합니다.
    1-7. 스택의 크기는 컴파일러가 결정하고 변경하지 않았다면 1MB로 한정됩니다.
    1-8. 스레드마다 스택이 존재하고 스택의 최대 크기는 1MB


2. 코드로 확인하기
    2-1. char szBuffer [1024 * 1024] -> 이를 출력
    2-2. szBuffer는 1MB입니다.
    2-3. 프로그램이 죽어버립니다. -> 즉, 스레드의 스택 크기를 벗어났기에 발생한 현상입니다.
        => Stack Overflow


3. 현대의 컴파일러는 함수의 매개변수의 개수가 많으면 일부는 레지스터로 보내서 스택의 크기를 줄여주는 최적화 작업도 합니다.
    => __fasecall
